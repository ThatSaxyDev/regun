# Absorb during freeze; release with the earned pushback

The creator requested a stronger, unified beat in the normal phone game. The
survivor now anticipates/absorbs/contains while the world is held. The closing
impact pose and short outward body accent begin at the same simulation boundary
as the existing recovery pulse. Settle frames play nonblocking after resume,
instead of finishing the full animation before the pulse. No extra pulse, damage,
invulnerability, healing, shove strength, radius or attack cancellation was added.

Native confirmation completion consumes the pending recovery flag and emits the
pulse immediately, without advancing world clocks or calling a zero-delta world
update. The cosmetic release is armed only by accepted selection, consumed once
beside that pulse and omitted on static crash restore. Pause/background freezes
both phases. Death/restart/route disposal cancel presentation. Damage has visual
priority. Reduced Motion keeps its settled body and quiet static accent; no body
flash or flying release fragments.

The incoming currents arrive later and the contained body charge stays visible
until release. The local actor burst and cool stepped pressure rim have stronger
contrast; camera and screen remain steady. All accepted rewards share the six
recipes. Mobility uses the leg charge; resilience/healing uses the brace; primary
power/ordnance uses the grounded absorption; focus/penetration/range uses deflection;
fire uses embers; ammunition/reload/devices/lightning uses hand charge/command.
This is category-based presentation reuse, not a promise of a new mechanic.

Online source also consumes the pulse at the authoritative confirmation boundary
without advancing world clocks, stamps `released`, and renders the release only
from that accepted authority. The client tolerates split table delivery and never
replays release after reconnect. Old servers keep their safe original flow. This
work did not deploy the hosted module; do not claim production co-op acceptance.

Signed `lib/main.dart` release built in30.0s, installed/launched on the creator's
physical iPhone in12.8s, retaining1.0.0+24 and existing app data. It boots normal
Home; no review launcher, timing choices or special testing mode is needed.
The earlier exported IPA predates this final impact adjustment and is superseded
for this visual change. No new TestFlight upload or numeric admin publication.

Targeted native runtime/recovery/normal-game/controller tests pass. Server typecheck
and184 tests pass, including a zero-clock release/one-pulse regression. Client
ledger tests cover split delivery and reconnect without replay. Analyzer is clean.
These checks and installation do not establish physical visual/audio acceptance.
