# Resting weapon aim and upgrade recovery

Release stays **1.0.0+7**. Implemented 21 October 2026 following creator playtest feedback.

## Gun pose while running

`WeaponHeading` keeps deliberate aiming immediate, including during reload. After 0.65 active seconds without aim input, a moving survivor's gun turns toward movement at up to 8 radians/second using the shortest angular route. Standing still holds the current direction. Pause, picker and deployment do not advance native rest timing. Reduced Motion settles directly after the same delay.

The same presentation model serves solo and online. The online fighter view already exposes `fireHeld`; deliberate input stays authoritative for firing. The local client sends its settled resting aim through normal movement input, and remote survivors render the same rest behavior. Grenade drag aiming remains independent.

## Confirmed-upgrade force pulse

An accepted XP, supply or fusion selection queues one pulse when gameplay resumes. Opening, rerolling, banning, pausing or replaying an expired choice does not trigger it. Co-op waits for the shared picker to finish; automatic timeout selections use the same confirmation path. This is recovery space, **not invulnerability**.

| Contract | Value |
| --- | --- |
| Radius | 250 world units, including intersecting enemy bodies |
| Enemy damage | 1, secondary damage with no primary-hit procs |
| Ordinary enemy displacement | Up to 145 units over 0.32s, scaled by existing mass resistance |
| Visual lifetime | 0.5s |
| Projectile clearing | One immediate pass through nearby hostile bullets |
| Protection/healing | None added by the pulse |

Walls block enemy damage and displacement; body occupancy and arena boundaries constrain every push. Bosses, nests and sentinels stay planted. Normal attacks remain live, and the pulse does not clear floor hazards, lasers or delayed attacks. Hostile bullets intersecting the radius at release are destroyed; bullets outside it, friendly rounds, grenades and bullets fired afterward remain. It is not an ongoing projectile shield.

Native accepted selections emit a dedicated notifier event. Pending release is checkpointed and validated; already-applied damage is not replayed. Server progress stores a pending flag set by the validated `choose` path and consumed once on the next active simulation frame. No new public tables or client damage authority were introduced.

The cool, broken pixel pressure rim and short filtered pressure/metal sound distinguish this effect from ember mine/grenade explosions. Reduced Motion uses a stationary fading rim. The audio is generated by `tool/generate_ordnance_audio.py`, included in full weapon-audio regeneration, prewarmed and overlap-limited. Existing recorded CC0 provenance remains in `art/source/audio/README.md`; peak/RMS/hash metadata is in `docs/art/ORDNANCE_AUDIO_MANIFEST.json`.
